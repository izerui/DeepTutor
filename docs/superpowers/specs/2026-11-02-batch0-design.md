# 第 0 批详细设计：修复与来源统一

> 日期：2026-11-02
> 状态：待确认
> 上级方案：`2026-11-02-teaching-direction-roadmap.md` 第 9 节和第 13 节第 0 批

第 0 批共 7 项，做完后：发给谁、从哪来处处清楚；账号变化不留尾巴。

---

## 1. 管理员可以重置第一个管理员的密码

- **现状**：只有第一个管理员本人能改自己的密码。别的管理员去重置，会被拒绝（403）。
- **改法**：
  - 去掉这个限制，所有管理员都能重置任何人的密码（D20）。
  - 重置后，他其他地方的登录全部失效（已有）。
  - 「第一个管理员不能删除」保持不变。
- **测试**：另一个管理员重置第一个管理员的密码成功，他的旧登录失效；删除第一个管理员仍被拒绝。

## 2. 第一次公开时必须选好发给谁

### 规则

适用于书、知识库、练习集、精通之路。

| 发布者 | 第一次公开时 |
|---|---|
| 有任课班的老师 | 弹出范围选择，预选他任课的全部班，可以改 |
| 没有任课班的老师、管理员 | 弹出范围选择，什么都不预选，必须选了才能确认 |

- 「全部」放在选项里，要主动勾。
- 已经设过范围的内容，再次公开时沿用上次的范围，不再弹出。
- 从没设过范围的老内容，不受影响，照旧按「全部」处理，直到发布者去改范围。

### 后端

- **公开接口加一个可选的「范围」参数**：书改公开、知识库改公开、练习集发布、精通之路发布，都加。
  - 带了范围：和公开一起写入，同一步完成。
  - 没带范围、发布者有任课班：用任课班（和现在一样）。
  - 没带范围、发布者没有任课班：拒绝公开，提示「请先选择发给谁」。
  - 这一条改掉了现在「没有班就等于全部」的做法。
- **精通之路**：发布框里勾的学生就是范围（已有）；一个没勾、又没有任课班时，拒绝发布。
- **精通之路发布时顺带公开的私有书和知识库**：发布框里选了「公开」的，范围跟这条精通之路一样（勾的学生，或者任课班）。
- **系统代码**（迁移、维护）公开内容时不设范围，等同「全部」，和现在一样。

### 前端

- 新增一个公用的「选择发给谁」弹窗，复用现有发布范围编辑器的选人、选班部分。
- 书、知识库的「改为公开」，练习集的「发布」：第一次时先弹这个窗，确认后才真正公开。
- 精通之路发布框：没有任课班又没勾学生时，「发布」按钮不能点，并提示原因。

### 测试

- 有班的老师不带范围公开：范围等于任课班。
- 没班的老师、管理员不带范围公开：被拒绝。
- 带范围公开：范围正确，中间没有对所有人可见的时刻。
- 再次公开沿用旧范围。
- 老内容不受影响。

## 3. 学生写的答案不进系统成绩库

- **现状**：上一轮为了「重新打开练习集能填回上次的答案」，把学生的答案存进了系统成绩库。
- **改法**：
  - 系统成绩库只存每题的对错和得分，不存答案。
  - 重新打开练习集时，从学生自己的题库里取他上次的答案，题库里本来就存着。
  - 已经存进去的答案，读的时候忽略，不再给任何人看。
- **测试**：交卷后，系统成绩库里没有答案；重新打开时，答案能从题库里填回来；老师的成绩表里看不到答案。

## 4. 精通之路引用的资料，有学生用不了时提醒

- **现状**：老师的精通之路引用了别人的书或知识库，而这些资料的范围不包括他的学生时，学生用不了，老师却不知道。
- **改法**：
  - 发布前的检查里加一项。对每一个不属于发布者本人的被引用资料，用资料自己的发布范围，去对比这条精通之路会发给的学生（勾的学生，或者任课班的学生）。
  - 有人用不了，就列出资料名和用不了的人数，提示「这些学生看不到这份资料，请让资料主人放宽范围，或换成你自己的资料」。
  - 只提醒，不拦。
- **测试**：引用了范围不够的资料时，发布前的检查给出提醒和人数；范围够的不提醒。

## 5. 来源统一

### 后端

- 新增一个判定函数：给一项内容和当前用户，返回来源。

  | 来源 | 什么时候 |
  |---|---|
  | `own`（我自己的） | 是自己的 |
  | `school`（学校发布） | 发布者当前是管理员 |
  | `teacher`（老师布置 · 某老师） | 发布者当前是老师 |
  | `shared`（某某分享） | 其他情况，只有旧数据会出现 |

- 下面这些列表，每一项都加上 `source` 字段：书、知识库、精通之路、学生的练习集列表。
- 题库里每道题的出处（来自哪个练习集、哪条精通之路）已经有了，这次只统一显示。

### 前端

- 新增一个来源标签组件，和一个「按来源分组」工具。
- 学生看到的书、知识库、精通之路、练习集列表，按「老师布置」「学校发布」「我自己的」分组。各列表原来各自的标签（「某某分享的」「公开的」「老师布置」分组等），全部换成这一套。
- 老师、管理员看到的列表也带标签。别的老师发给自己的显示「某老师分享」，不显示「老师布置」。
- 六种语言同步。

### 测试

- 判定函数四种来源都覆盖。
- 发布者角色变了，标签跟着变。
- 各列表接口都带上 `source`。
- 前端分组正确。

## 6. 管理员可以撤回别人的练习集

- **现状**：练习集只有作者本人能操作，管理员连撤回都做不了，不符合「管理员兜底」。
- **改法**：
  - 管理员可以对别人的练习集点「撤回」（归档）。
  - 管理员点「删除」时，实际执行撤回。
  - 管理员不能修改题目、不能改范围、不能看学生成绩（成绩表只给作者看）。
  - 管理员的练习集列表里能看到别人已发布的练习集，只显示「撤回」操作。
- **测试**：管理员撤回别人的练习集成功，学生那边随即看不到；管理员改题、改范围、看成绩都被拒绝。

## 7. 老师改成学生时转交内容

- **现状**：老师被改成学生后，他发布过的内容仍归他。他已经是学生，却还挂着这些内容。
- **改法**：老师改成学生（或其他非老师角色）时，像删号一样，把他发布过的内容转给执行操作的管理员，学生那边照常可用，来源变成「学校发布」。具体转交：
  - 公开的、或被引用的书和知识库；
  - 他的全部精通之路模板；
  - 发布过的练习集。
- **不转交的**：从没发布过的草稿和私有内容。这些是他个人的，账号还在，就留给他。
- **文件位置不动**，只改归属，和删号时一样。
- 转交在改角色时立即完成。转交失败的部分会记下来，管理员可以在「账号交接」里重试（已有机制）。
- **测试**：老师改成学生后，他已发布的内容归属变成管理员，学生照常能用；他的私有内容和草稿仍归他；转交失败可以重试。
