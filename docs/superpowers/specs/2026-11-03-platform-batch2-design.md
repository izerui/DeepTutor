# 学习平台 第 2 批详细设计：去掉班级

> 日期：2026-11-03
> 状态：已确认（2026-11-03），已实现
> 上级：`2026-11-03-learning-platform-direction.md`（第 8、9.2、9.3 节）；接着 `2026-11-03-platform-batch1-design.md`

做完后：界面上不再有班级。原来经班级、指定个人收到内容的人，东西都还在；以后只靠「加入」。老师、管理员也能加入任何内容来学。

---

## 1. 范围

**本批做：**

1. 旧数据迁移（上级 9.2、9.3）：原来发给班级、院系年级、个人的内容和任务，接收者固定成「已加入」；班级权限写进个人设置。
2. 迁移完成后，班级不再给任何人任何东西（访问、权限、AI 用量、「我的学生」）。
3. 从界面上撤掉班级相关入口。
4. 学生权限去掉「按班」这一层。
5. 注册不再带进班邀请。
6. 任务只放在课程里，不再单独发；练习集、精通之路不再自动变成任务。
7. 老师、管理员也能加入精通之路、练习集、课程。
8. 老师工作台、管理员首页改版。
9. 管理员的分类管理、标签合并；管理员可以改别人上架内容的分类和标签。

**不在本批（第 3 批）：**

- 课程公告；
- 课程和精通之路的报告、「需要关注」、老师端补练；
- 作业转交规则（离任老师的作业改转管理员）。

在第 3 批之前，班级报告、班级公告、「需要关注」从界面上暂时消失。

## 2. 旧数据迁移

后端启动时自动跑一次，记下已完成，可以重复运行。跑之前备份发布范围库、上架库和账号库。

### 2.1 内容和任务（上级 9.2、9.3）

**对象：** 所有还带着接收者（班级、院系年级、指定个人，或「全部」）的内容和单独发的任务，书、知识库、精通之路、练习集、课程、任务都算。另外还有一类：没有发布范围记录、但手动分配过学生的旧精通之路。

**处理：**

1. 迁移那一刻能收到它的人，全部写成「已加入」，来源记为迁移。
   - 书、知识库：所有角色都算。
   - 其余几类：只算学生，和原来的规则一致。
   - 作者本人不算。
2. 接收者清空。以后它只靠加入的人。
3. 课程迁移完，再把课程里的任务和引用的内容按加入记录补齐。
4. 这些内容的上架状态不变。没上架的仍是「未上架」，作者可以去申请。

**例外：** 学生以前公开过的书、知识库不动（上级 9.3）。

### 2.2 权限和 AI 用量（上级 9.3）

- 对每个学生，算两遍可用功能：一遍带班级层，一遍不带。
  - 只有在班级层确实改变了结果、而且他自己没有单独设置的那几项，才写进他的个人设置。
  - 这样迁移前后，每个学生能用的功能完全一样。
- AI 每日用量同理：班级层让他的上限变了，就把迁移前的实际上限写进他的个人设置。

### 2.3 迁移后班级不再起作用

迁移成功后记一个标记「班级已停用」。从这以后：

- 进了哪个班，不再带来任何内容、任务、权限、AI 用量。
- 「老师的学生」改成「加入了这位老师内容的学习者」。
  - 用到这个概念的地方：练习集成绩表、补练能发给谁、精通之路手动加人的范围。
- 老师不能再重置学生的密码，只有管理员能。
- 新发布的内容不再默认发给任教的班，接收者为空，只靠加入。第 1 批里旧调用（比如补练）保留的老规则，到这里一起结束。

迁移失败时不打这个标记，班级照旧起作用，下次启动再试。这样不会出现「班级停了、东西还没转过去」的空档。

班级、院系、年级、邀请、班级公告的数据都留在库里，不删。

## 3. 界面上撤掉的

| 撤掉 | 换成 |
|---|---|
| 侧栏「班级」入口 | 去掉 |
| 班级页 `/classes`（建班、邀请、任课老师、院系年级、按班权限、班级报告、班级公告） | 打开时显示「班级功能已停用，去学习市场看看」 |
| 任务页里「发给谁」 | 去掉，见第 5 节 |
| 学生首页的班级公告 | 去掉（第 3 批换成课程公告） |
| 老师工作台「我的班」「需要关注的学生」 | 去掉（「需要关注」第 3 批放进课程报告） |
| 管理员首页「班级、院系和年级」入口 | 换成「分类和标签」 |
| 学生权限编辑里「默认跟随所在班级」的说明 | 改成「默认跟随系统默认」 |
| 注册页的进班邀请、`/join/邀请码` 页面 | 注册页去掉邀请；邀请页显示「邀请链接已停用」 |
| 老师重置学生密码 | 去掉 |

## 4. 注册

- 开放注册时，谁都可以自己注册。
- 关闭注册时，只能由管理员建号。
- 带邀请码的注册请求一律当作普通注册处理：开放时照常注册，不进任何班；关闭时拒绝。
- 关闭时的提示从「找老师要邀请链接」改成「请联系管理员开通账号」。

## 5. 任务只在课程里

- 老师新建任务只能在课程里建。任务页的「新建任务」去掉，换成提示「在课程里添加任务」。
- 单独发布任务（不在任何课程里）后端拒绝。课程发布、往已发布课程里加任务时，任务照旧自动发布。
- 已经单独发出的旧任务：第 2.1 节固定了接收者，照常有效。老师照常能改说明、截止时间，能批改、退回、撤回。
- 老师的任务页保留，用来编辑和批改。列表按课程分组；不属于任何课程的旧任务放在「其他」组。
- 练习集、精通之路不再自动显示成任务（取消原来的 R23）。
  - 学生加入后，它们出现在各自的列表里。
  - 首页「待完成」和日历只列课程里的任务和旧任务。
  - 已经记下的完成记录保留。

## 6. 老师、管理员也能加入

- 精通之路、练习集、课程的「加入学习」对所有角色开放（作者本人除外）。
- 原来只认学生的地方，改成「学生，或者加入了它的人」：
  - 精通之路的学习副本：加入了就生成，在自己的默认工作区里；
  - 练习集的作答和成绩：作者的成绩表里也列出加入的老师、管理员；
  - 课程、任务和交作业；
  - 首页「待完成」。
- 学生角色专属的东西不变：AI 用量上限只管学生，学生权限只管学生。

## 7. 老师工作台和管理员首页

**老师工作台：**

| 区块 | 内容 |
|---|---|
| 待批改 | 不变 |
| 我上架的内容 | 第 1 批已有 |
| 我发出去的内容和完成率 | 不变，人数改按加入的人算 |
| 我自己在学的 | 不变，加上我加入的内容 |

**管理员首页：**

- 账号；
- 上架审核（带待审数量）；
- 分类和标签；
- 我上架的内容；
- 自己的学习区。

## 8. 分类管理和标签合并

页面 `/admin/catalog`，只有管理员能进。

### 8.1 分类

- 在预置分类上可以做这些调整：
  - 改名：中文名、英文名；
  - 隐藏和显示；
  - 同级内上移、下移；
  - 新加一项：可以加学段，也可以在学段下加一级学科，或在一级学科下加二级学科。
- 预置的项不能删，只能隐藏。自己加的项没有内容在用时可以删，有内容在用时只能隐藏。
- 隐藏的项：
  - 不出现在市场筛选和上架的可选项里；
  - 已经用了它的内容保留原分类，介绍页照常显示名称；
  - 作者再保存时，隐藏的项不能新选进来，原来已有的可以留着。
- 只在库里存调整的部分，预置清单还在代码里，各项的固定编号不变。

### 8.2 标签

- 列出所有上架内容用到的标签和次数。
- 合并：把标签 A 并进标签 B。
  - 所有内容上的 A 换成 B，重复的去掉；
  - 以后有人再填 A，自动换成 B；
  - 合并可以撤销，但撤销只停止自动替换，已经换掉的不改回去。

### 8.3 改别人内容的分类和标签

- 管理员在上架审核页「已上架」那一栏，可以改任何内容的学段、学科、难度、标签。
- 不能改标题、简介和内容本身。
- 每次修改记一条审核记录。

**新接口：**

- `GET /api/catalog/admin/tags`：标签列表和次数。

## 11. 测试和完成标准

**后端：**

- 迁移：
  - 内容和任务：发给班级、院系年级、个人的五类内容各一条，单独发的任务一条，都要验证接收者变成已加入、范围被清空；
  - 课程：迁移后里面的任务能收到；
  - 学生权限：迁移前后每个学生的结果不变，AI 上限也不变；
  - 重复运行不出错；
  - 失败时不打停用标记。
- 停用后：
  - 进班不再带来内容；
  - 老师的学生 = 加入的学习者；
  - 老师不能重置学生密码；
  - 首次发布不选接收者也能成功。
- 注册：带邀请码时不进班；关闭注册时邀请码不能注册。
- 任务：单独发布被拒；课程里加任务照常发布；练习集、精通之路不再出现在任务列表。
- 老师、管理员加入：精通之路生成副本，练习集能作答且出现在成绩表，课程收到任务。
- 分类和标签：
  - 分类：改名、隐藏（隐藏后筛选和上架选不到、旧内容保留）、新增、删除自己加的项；
  - 标签：合并后旧标签被替换、以后输入自动替换、撤销合并；
  - 管理员改别人内容的分类：能改分类，不能改标题。
- 已有的第 0～4 批测试：凡是依赖「进班就收到」的，改成在迁移前的状态下测，或者改用加入。

**前端：** 被撤掉的入口确实不见了；分类管理页；任务页分组；六种语言检查。

**浏览器实测：**

1. 准备数据：迁移前，老师把练习集发给一个班，并单独发一个任务。
2. 重启后迁移完成：学生仍能做那套练习集和那个任务。
3. 侧栏没有「班级」。
4. 注册页没有邀请。
5. 老师在课程里加任务，课程学习者收到。
6. 老师加入别人上架的练习集并作答。
7. 管理员改一项分类的名字并隐藏一项，市场筛选随之变化；合并两个标签。

**全量测试：** 后端、前端全部通过，然后本地提交，不推送。

## 12. 风险

- 第 0～4 批有不少测试依赖「进班就收到」，要改的测试会比较多。原则是测试改成「迁移前」或「加入」两种情形之一，不删测试覆盖的规则。
- 「班级已停用」之前和之后行为不同，所以每个改动点都要在两种状态下各测一次。

## 13. 实现时的调整（2026-11-04）

- **改动都跟着「班级已停用」标记走**：本批的行为变化（班级不再给东西、注册不认邀请、任务只能随课程发布、练习集和精通之路不再变成任务、老师不能重置学生密码、首次发布不选接收者）都在打了标记之后才生效。标记之前一切照旧，所以第 0～4 批的测试不用改，仍然测的是迁移前的规则。新装的系统启动时没有旧数据，会直接打上标记。
- **老师、管理员加入**：不看标记，第 2 批起就开放。
- **任务列表带所属课程**：老师的任务列表和任务详情多了所属课程，用来分组；不在任何课程里的草稿任务不显示「发布」按钮。
- **任务页多了「我加入的课程」**：老师、管理员加入课程后，在这里看到并完成课程里的任务。
- **分类管理接口**：按节点分开，分别是改名或隐藏、新增、上移下移、删除，每次返回整棵树。
- **浏览器实测已覆盖**：
  - 在实测环境里，先让老师用旧方式把练习集和单独任务发给班，再跑迁移：学生仍能做那套练习、看到那个任务；
  - 侧栏没有「班级」，班级页显示停用说明；
  - 老师任务页按课程分组、没有新建任务；在课程里新建作业并发布课程，不用选发给谁；
  - 课程上架后，另一位老师加入，在「我加入的课程」里看到作业；
  - 管理员隐藏一个学段后，公开分类里不再有它；合并标签后，课程上的标签随之替换。
- **浏览器实测未覆盖**：注册页（自动测试覆盖了带邀请码和关闭注册两种情况）。
