# 从消息打开小老师（借鉴上游，2026-11-20）

> 状态：用户同意直接做（「做吧」）。调研见 `.superpowers/tutor-practice-survey.md`。

## 1. 现在的问题
- 只能先选中一段文字才能问小老师；想就整条回复追问，没有入口。
- 小老师对话没记下是从哪条消息问的：刷新后标签没了，再问又开新对话，旧对话只能去学习空间历史里找。

## 2. 要做的
1. **整条回复问小老师**：每条 AI 回复的操作栏加「问小老师」，不用选文字。服务器按消息 id 自己读原文，不信页面传来的文字。
2. **记住来源**：小老师对话记下来源消息、选中的文字（整条回复时为空）。
3. **消息下面的标记**：有小老师对话的回复下面显示一行「小老师 · N」，点开列出这些对话，可以打开、删除、解除关联。
4. **接着问**：同一条消息、同一段选中文字（或都是整条回复）再问时，打开原来的对话接着问，不再开新的。
5. **回到原消息**：小老师对话里有「回到原文」，滚动到来源消息并高亮；原消息已删除或不在当前分支时提示「原消息已不在当前对话中」。
6. **原消息被删除或重新生成**：小老师对话保留，只解除关联（列表里显示为「原消息已删除」）。
7. 以前的老对话不补来源（以后再说）。

## 3. 不做
- 命令面板入口（我们没有命令面板）。
- 侧边标签按账号保存（以后单独做）。
- 侧栏「一次练习合成一条」：我们的侧栏本来就不逐题列练习，不需要。

## 4. 顺带核实
- 测验里每道题的「追问」可能各自开了一个独立会话、没记父会话，导致侧栏多出几条会话。先实际确认；确认属实就给追问会话记上父会话，让它们不单独出现在侧栏，而在原会话里能找到。

## 5. 验证
- 后端全量 + 回环测试；前端类型检查、vitest、node 测试、语言检查、契约检查。
- 新测试：整条回复提问按消息 id 读原文；来源记录；同消息同文字复用对话；删除和重新生成后解除关联；别人的会话、别人的消息不能挂。
- 浏览器（有模型时）：问小老师 → 标记出现 → 刷新后还能从标记打开 → 回到原文 → 删除原消息后对话还在。

## 6. 实际结果（2026-11-20）
- 提交：facba0263（后端）、3244f4b06（前端）、245582b0d（测验追问挂父会话）。
- 整条回复问小老师：回复操作栏加了「问小老师」。服务器按消息 id 从父会话读原文，页面传来的文字一律不用；没有消息 id 时拒绝。
- 来源记录：小老师对话记下 `tutor_scope`（selection / message）、`tutor_selected_text`（前 2000 字，整条回复为空）、`tutor_source_message_id`。
- 消息下面的标记「小老师 · N」：可以打开、解除关联、删除（移植上游 MessageThreadMarker / useSessionThreads / groupThreadsByMessage，接在我们自己的选中文字小老师上）。新接口 `GET /api/sessions/{id}/threads`；`PATCH .../organization` 支持 `tutor_source_message_id`（null 解除关联，给 id 是移到同一父会话的另一条消息）。
- 接着问：同一条消息、同一段文字（或都是整条回复）再问时打开原来的对话，刷新后从标记打开会读回历史。
- 回到原文：滚动到来源消息并高亮；找不到时提示「原消息已不在当前对话中」。
- 删除和重新生成：小老师对话保留，只解除关联，记 `tutor_source_deleted`，对话里和学习空间历史里显示「原消息已删除」。之后在这个对话里接着问不会出错，也不会重新挂回去。
- 只能挂自己的：每个用户有自己的会话库，别人的会话、别人的消息找不到，开小老师会失败，也移不过去。同一用户另一个会话的消息也挂不上。这些都有测试，包括管理员和学员两个账号。
- §4 核实：属实。用真实运行时复现，测验追问会话的 preferences 里没有 `parent_session_id`。现在记成父会话（`session_kind = "quiz_followup"`，继承工作区和课程），侧栏不再单独显示；学习空间历史里在原会话下面，标「题目追问」。父会话不是自己的就保持独立。老的追问会话不迁移。
- 没做：老对话补来源（按 §2.7）；PocketBase 存储删除消息时解除关联（删消息接口本来直接用 SQLite，重新生成走 PocketBase 时不会解除关联）；浏览器实测（隔离环境没有模型，也不能占用现有端口）。
- 验证：后端全量 14853 个用例，除 5 个已知的 mineru `/bin/ps` 沙箱失败外都通过（126 个跳过）；回环 22 个通过。前端 tsc、vitest 1580 个、node 测试 1444 个、语言检查、契约检查都通过。

## 7. 老对话补来源（2026-11-24，移植上游 50f1d9f52、58afb10b5、75d65b7de）
- 11-20 之前的小老师对话只记了 `parent_session_id` 和 `session_kind`，没有 `tutor_selected_text`，也没有引用附件。唯一可靠的记录是每条助手回复 `metadata.model_turn.system` 里的侧栏提示词（v1.6.9 起保存）：原消息全文或摘录、消息角色、精确选中的文字、来源会话。
- 打开某个对话的「小老师」列表（`GET /api/sessions/{id}/threads`）时惰性补：提示词里的来源会话必须就是父会话；只在本账号、本父会话的用户/助手消息里按记录的角色找；原消息全文须与候选相等，摘录须包含在候选里；恰好一条才写入 `tutor_source_message_id`、`tutor_scope=selection`、`tutor_selected_text`。多条或没有都不写。
- 条件写入：仍没有 `tutor_source_message_id` 键、没有 `tutor_source_deleted`、父会话和类型没变时才写，不改 `updated_at`；SQLite 用 `BEGIN IMMEDIATE`，PocketBase 用同一把 `_prefs_lock` 并在锁内读。解除、移动、删除原消息都会写这个键，所以并发时它们优先。
- 失败记 `tutor_source_backfill_failed_at`（并在内存里记），一小时后才重试；单次请求最多处理 50 个。
- 补不回来的：v1.6.9 之前的对话（没有存提示词）、首轮就失败没有助手回复的、原消息后来被改/重新生成/删除的、原文在父会话里出现多次的。
