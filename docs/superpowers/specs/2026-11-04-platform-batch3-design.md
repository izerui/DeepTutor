# 学习平台 第 3 批详细设计：课程和精通之路的学习者

> 日期：2026-11-04
> 状态：用户已同意直接开始（2026-11-04），已实现
> 上级：`2026-11-03-learning-platform-direction.md` 第 8.2 节；接着第 2 批

做完后：老师按课程、精通之路带学习者——发公告、批改点评作业、看学习情况、找出需要关注的人、一键补练。第 2 批暂时撤掉的报告、公告、「需要关注」以新的方式回来。

---

## 1. 学习情况报告（课程、精通之路）

**谁能看：** 只有这门课或这条路线的作者，而且作者得是老师。管理员看不到学习数据，规则不变。

**看谁：** 当前所有加入了它的人，不分角色，不含作者本人。加入的方式包括自己加入、经课程带入、迁移来的。

**内容：** 每个学习者一行，可以按最近 7 天、30 天、全部筛选。

| 列 | 课程 | 精通之路 |
|---|---|---|
| 最近学习、学习时长、作答数 | ✓ | ✓ |
| 任务完成：几项完成了几项 | ✓ | |
| 作业：待批改、已退回、已批改 | ✓ | |
| 课程里练习集的成绩 | ✓ | |
| 这条路线：掌握了几个知识点、一共几个 | 课程里引用的路线 | ✓ |
| 需要关注标记：7 天没学、有逾期、错题增多、卡住的知识点 | ✓ | ✓ |

**其他：**

- 精通之路另有「每个知识点谁掌握了」的分布，可以从这里对没掌握的人一键补练。
- 点一个学习者，看他在这项内容上的详细情况：各知识点的掌握情况、各练习集的成绩。
- 可以导出成 CSV。
- 计算方式沿用原来的班级报告，只是把「班里的学生」换成「加入的学习者」。

## 2. 需要关注

- 老师工作台的「需要关注」恢复。看的人是加入了这位老师内容的学习者，规则和以前一样：7 天没学、有逾期、错题明显增多、某个知识点卡了很久。
- 每个人旁边标出是哪门课或哪条路线，点开进那份报告。
- 报告里也显示同样的标记。

## 3. 公告

- **谁发：** 课程和精通之路的作者，可以给加入的人发公告，也可以置顶。
- **谁改：** 作者能改、能删；管理员只能删。
- **谁收到：** 加入了这门课或这条路线的人，收到站内通知「X 发了公告」。
- **在哪看：**
  - 学习者那边：课程页、精通之路的内容介绍页，以及首页「公告」区（自己加入的内容里最新的 3 条）；
  - 作者那边：在课程页、精通之路的管理里发和管理。
- **退出了就看不到。** 内容被撤回后，公告也跟着看不到。
- **旧的班级公告：** 保留在库里，不显示。

## 4. 补练

- 老师在报告里选出错得多的题，或者没掌握的知识点，生成补练练习集，发给选中的学习者（默认是没掌握的那些人）。
- 生成和出题沿用现有的补练功能。区别只在入口：从班级报告挪到了课程和路线报告。
- 能发给谁：只能是这位老师内容的学习者。
- 补练练习集不上架，只给选中的人。

## 5. 学习者平均分

- 原来的「全班平均」改叫「学习者平均」：所有交过的人的平均分，人数不到 3 个不显示。
- 只改叫法，计算方式不变。

## 6. 资料被撤回

**补一个漏洞：** 书或知识库被管理员撤回后，引用它的精通之路的学习者也不能再经路线读到。

**通知：** 下面三种情况，通知其他老师——他们已发布的精通之路引用了这份资料，或者课程里有读这本书的任务：

- 资料被管理员撤回；
- 作者把资料设为私有；
- 作者删除了资料。

**通知规则：**

- 同一份资料、同一项内容，一天只通知一次。
- 资料作者自己的内容不通知。
- 作者下架资料不通知，因为已经在用的人不受影响。

## 7. 作业转交

不用改。离任老师的作业任务直接转给接手的管理员，作业保持「待批改」。原来「优先转给同班另一位老师」的规则已经不存在了，因为没有班级。本批用测试固定这条规则。

## 8. 后端

**新增：**

| 文件 | 内容 |
|---|---|
| `catalog/reports.py` | 课程、精通之路的报告。复用班级报告的计算，学习者名单换成加入的人 |
| `catalog/announcements.py` | 公告。存在上架库的新表 `content_announcements` 里 |
| `catalog/material_notice.py` | 第 6 节的通知 |

**改动：**

| 位置 | 改什么 |
|---|---|
| 工作台 | 「需要关注」恢复，每个人附上一项他加入的内容，用来链接到报告 |
| 首页 | 「公告」改为读取加入内容的公告 |
| 书、知识库能不能读 | 被撤回时，经引用也不能读，只有作者和管理员能读 |
| 上架 | 撤回时、设为私有时、删除时，触发第 6 节的通知 |
| 资料撤回通知 | 班级停用后，原来按接收者对比的检测停掉，改由第 6 节的规则负责 |

**新接口：**

- 报告：`GET /api/catalog/reports/{kind}/{id}?days=`，以及 `/points`（精通之路的知识点分布）、`/export`、`/learners/{user_id}`。
- 公告：`GET/POST /api/catalog/items/{kind}/{id}/announcements`；`PUT/DELETE /api/catalog/announcements/{id}`；`GET /api/catalog/announcements/mine`（首页用）。

## 9. 前端

- **报告页 `/reports?kind=&id=`：**
  - 学习者表格、时间段筛选、导出、学习者详情；
  - 精通之路的知识点分布，以及补练入口；
  - 课程报告里，各练习集也有补练入口。
- **入口：** 课程作者页上的「学习情况」；精通之路管理对话框里的「学习情况」。
- **公告：**
  - 作者在课程页、精通之路管理里发公告；
  - 学习者在课程页、精通之路的内容介绍页、首页看到。
- **工作台：** 「需要关注」恢复，链接到报告。
- **叫法：** 「全班平均」改成「学习者平均」。
- **通知：** 新增「公告」通知的文字。
- **文案：** 六种语言。

## 10. 测试和完成标准

**后端：**

- 报告：
  - 只有作者（老师）能看，管理员和其他老师不能；
  - 学习者 = 加入的人，退出的人不在里面；
  - 课程的任务完成、作业状态、练习成绩都对；
  - 精通之路的知识点分布对；
  - 导出的 CSV 对；
  - 学习者详情对。
- 需要关注：只看自己内容的学习者，并且带上对应的内容。
- 公告：
  - 发出后，加入的人收到通知；
  - 没加入的人、已退出的人看不到；
  - 作者能改，管理员能删，别人不能动；
  - 内容被撤回后公告看不到。
- 补练：从报告里发给学习者；发给不是自己学习者的人时被拒。
- 资料撤回：
  - 撤回后，精通之路的学习者经引用也读不到；
  - 其他老师收到通知，一天一次；
  - 下架不通知。
- 作业转交：离任老师的作业转给管理员。

**前端：** 报告页、公告的发布和查看、工作台的「需要关注」、叫法、六种语言检查。

**浏览器实测：**

1. 学生加入课程、交作业。
2. 老师在报告里看到他、批改作业、发公告。
3. 学生收到公告通知，并在首页和课程里看到公告。
4. 老师从报告补练。

**全量测试：** 后端、前端全部通过，然后本地提交，不推送。

## 11. 实现时的调整（2026-11-04）

- **资料撤回通知只在班级停用后发**：停用前沿用原来按接收者对比的通知，避免同一件事通知两次。
- **管理员看不到「学习情况」入口**：课程页和精通之路管理里，管理员不显示这个按钮。管理员不看学习数据，后端本来也会拒绝。
- **报告返回课程页**：从课程报告点返回，回到任务页的「课程」页签。
- **浏览器实测已覆盖**：
  - 学生加入课程，交作业；
  - 老师打开课程的学习情况：看到这个学生完成 1/2、作业 1 份待批改；
  - 老师发公告：学生收到通知，首页「公告」区能看到。
- **浏览器实测未覆盖**：
  - 精通之路的报告和知识点分布、从报告补练：测试环境没有模型，建不出精通之路，也生成不了补练题；
  - 批改作业：沿用原有流程，没有改动。
  - 这些都有自动测试覆盖。
