# 学习平台 第 1 批详细设计：上架 → 审核 → 市场 → 加入学习

> 日期：2026-11-03
> 状态：已确认（2026-11-03），已实现
> 上级：`2026-11-03-learning-platform-direction.md`（已确认，第 11 节的 4 条按建议执行）

做完后能走通：老师上架一份内容 → 管理员审核通过 → 学习者在市场里筛选、搜索找到 → 看介绍 → 加入学习 → 在自己的列表里学；作者主页能看到加入人数。

---

## 1. 范围

**本批做：**

- 预置分类：只读，上线自带。管理员调整分类放在第 2 批。
- 上架流程：提交、审核、驳回、下架、重新上架、撤回。
- 学习市场：筛选、搜索、排序；内容介绍页；作者主页；加入人数。
- 加入学习、退出学习。
- 五类内容的发布界面：「发给谁」换成「上架」。
- 旧数据迁移：上级第 9.1 节，即用「全部」范围发布的内容。
- 来源标签「学校发布」改叫「平台发布」。

**本批不做（第 2、3 批）：**

- 撤掉班级页面。
- 发给班级、个人的旧内容的迁移。
- 学生权限去掉班级层。
- 注册去掉邀请。
- 单独的任务。
- 分类管理、标签合并。
- 课程公告和报告等。

**本批的一个限制：** 老师、管理员能加入别人的书和知识库，暂时不能加入精通之路、练习集、课程。这三类的学习流程现在只认学生账号，第 2 批去班级时一起放开。市场里对他们显示介绍页，不显示「加入」按钮。

## 2. 上架状态

| 状态 | 在市场里 | 能新加入 | 已加入的人能学 |
|---|---|---|---|
| 未上架 | 否 | 否 | —（迁移来的成员照旧能学） |
| 待审核 | 否 | 否 | 同上 |
| 已驳回 | 否 | 否 | 同上 |
| 已上架 | 是 | 是 | 是 |
| 已下架（作者） | 否 | 否 | 是 |
| 已撤回（管理员） | 否 | 否 | **否**，显示「内容已不可用」，记录保留 |

**状态怎么变：**

| 动作 | 谁 | 前 → 后 | 通知 |
|---|---|---|---|
| 提交上架 | 老师 | 未上架、已驳回、已撤回 → 待审核 | 所有管理员 |
| 提交上架 | 管理员（自己的内容） | → 已上架 | — |
| 通过 | 管理员 | 待审核 → 已上架 | 作者 |
| 驳回 | 管理员，必须写原因 | 待审核 → 已驳回 | 作者，带原因 |
| 撤回申请 | 作者 | 待审核 → 未上架 | — |
| 下架 | 作者 | 已上架 → 已下架 | — |
| 重新上架 | 作者 | 已下架 → 已上架（审核通过过，不再审） | — |
| 撤回 | 管理员，必须写原因 | 已上架、已下架 → 已撤回 | 作者，带原因 |

**几条规则：**

- 撤回后，作者改完可以重新提交，要重新审核。审核通过后，原来加入的人自动恢复，进度都在。
- 撤回只改上架记录，不动内容本身。精通之路现有的「归档」不能恢复，所以撤回不走归档，改成在访问判断里统一拦（见 4.2）。
- 作者自己原有的「归档、设为私有」保持现状：所有人都不能再进。这时上架记录跟着变成「已下架」，内容恢复后作者可以重新上架。
- 每次状态变化都记一条审核记录：谁、何时、动作、原因。作者能看到最近的驳回或撤回原因。

## 3. 上架时填的信息

**表单字段：**

| 字段 | 规则 |
|---|---|
| 标题 | 必填，最多 80 字，默认取内容名称 |
| 简介 | 必填，最多 1000 字，默认取内容描述 |
| 学段 | 1～3 个 |
| 学科 | 1～3 个，每个都必须属于所选学段。可以选一级；有二级的，也可以选到二级 |
| 难度 | 入门、初级、中级、高级，选 1 个 |
| 标签 | 0～8 个，每个最多 20 字。自动去掉首尾空格；大小写不同算同一个，显示用第一次出现的写法 |

- 已上架的内容，标题、简介、分类、标签随时可以改，不审，立即生效。
- 待审核期间也能改，管理员看到的是最新的。

**提交前的检查**（不满足就不让提交，并说明原因）：

| 内容 | 要求 |
|---|---|
| 书 | 至少有 1 章正文 |
| 知识库 | 至少有 1 个文档已处理好；不能是外接连接器类的知识库 |
| 精通之路 | 至少发布过一版，没有归档 |
| 练习集 | 已发布、有题，没有归档 |
| 课程 | 已发布、至少 1 项，没有归档 |

- 只有内容的作者能提交，而且作者必须是老师或管理员。学生账号的上架接口一律 403，界面上也没有按钮。

## 4. 加入学习和访问

### 4.1 加入记录

- 每条记录：谁、哪项内容、什么时候加入、怎么来的（自己加入 / 经某门课程 / 迁移）、是否已退出。
- 加入：市场里的内容必须是「已上架」。重复加入什么也不变。
- 退出：标记已退出，学习记录全部保留。再次加入时原样恢复：精通之路的副本、练习的成绩、书的阅读进度都还在。
- 加入人数：当前没退出的人里，「自己加入」和「迁移」两种来源的去重人数。经课程带进来的不算在被引用内容的人数里。

### 4.2 访问怎么判断（一处改动）

现有的「谁能收到」都走发布范围这一层：书、知识库能不能读，精通之路的分配，练习集、课程、任务的收到，全都查它。本批只在这一层加一条：

- 读取一项内容的范围时，带上它的加入成员。
  - 「谁能收到」= 原来的接收者 ∪ 加入成员。
  - 上架记录是「已撤回」时，加入成员和原来的接收者都不算（作者本人除外）。
- 因此各类内容的具体代码基本不用动：
  - 书、知识库：加入后出现在自己的书架和知识库列表里，聊天里也能选。
  - 精通之路：加入后生成自己的学习副本（沿用现有的分配和副本机制）。退出时副本只是不再显示，再加入就回来。
  - 练习集：加入后出现在练习集列表里，可以作答。
  - 课程：加入后出现在课程列表里，收到课程里的全部任务。
- 加入成员只在读的时候合进去，不写回原来的发布范围表，所以不会和作者原来选的接收者混在一起。

### 4.3 课程带进来的内容

- 加入课程时，同时给这个人加上：课程里每个任务，以及任务引用的精通之路、练习集、书、知识库。来源记为「经课程」。
- 课程后来加了任务：给课程现有的所有成员补上。
- 退出课程：去掉经这门课带进来的记录。自己单独加入过的保留。
- 课程能引用什么（替换原来的「范围必须覆盖接收者」检查）：已上架的内容，或者课程作者自己的内容。课程里加别人没上架的内容，直接拒绝。

### 4.4 发布时不再选「发给谁」

- 精通之路、练习集、课程发布时，不再要求选接收者，也不再默认发给任教的班级。新发布的内容接收者为空，只有加入的人能收到。
- 书、知识库「上架」时自动设为公开，接收者为空。之后只有加入的人能读，作者能读，管理员能读（管理员原来就能看到所有公开的，用来审核和撤回）。
- 已有发布范围的旧内容，范围照旧生效到第 2 批。本批把编辑范围的入口从界面上撤掉。

## 5. 学习市场

### 5.1 页面

| 页面 | 地址 | 谁能看 |
|---|---|---|
| 学习市场 | `/market` | 所有登录的人，侧栏加入口「学习市场」 |
| 内容介绍 | `/market/item?kind=…&id=…` | 同上 |
| 作者主页 | `/market/author?id=…` | 同上 |
| 上架审核 | `/admin/review` | 管理员，管理后台加入口，带待审数量 |

**市场页布局：**

- 顶部：搜索框和排序（最新上架 / 最多人学）。
- 左侧：筛选条件。
  - 学段、学科：选了学段后，学科只列这些学段下的；学科可以展开到二级。
  - 内容类型、难度。
  - 标签：显示最常用的 20 个，可以搜。
  - 作者：可以搜。
- 每个选项后面带数量。数量的算法：其他条件都套上，只把当前这一项放开来数。
- 已选的条件在结果上方排成一排，每个可以单独去掉，也可以一键清空。
- 条件写在地址里，刷新和分享都保留。
- 结果是卡片列表，每页 24 张。
  - 卡片内容：类型图标、标题、作者、学段和学科、难度、加入人数、「已加入」标记。
  - 没有结果时显示「没有符合条件的内容」，并给一个「清空条件」按钮。

**内容介绍页：**

- 标题、简介、作者（点进作者主页）、分类、难度、标签、加入人数、更新时间。
- 预览：

| 内容 | 预览什么 |
|---|---|
| 书 | 章节目录 |
| 精通之路 | 模块和知识点名称 |
| 练习集 | 题量、各题型数量、总分（不露题目） |
| 课程 | 条目列表（任务名和类型） |
| 知识库 | 文档名列表 |

- 按钮：
  - 没加入时：「加入学习」。
  - 已加入时：「去学习」，直接跳到对应页面，另有「退出学习」。
  - 作者本人看到的是「管理上架」。

**作者主页：** 作者名、总加入人数，上架内容按类型分组，每项显示加入人数。

**审核页：**

- 待审列表，最早提交的排前面。
- 点开看上架信息，以及只读的完整内容：
  - 书：目录，可以逐章打开正文；
  - 精通之路：最新一版的大纲和知识点；
  - 练习集：最新一版的全部题目和答案；
  - 课程：条目；
  - 知识库：文档列表。
- 「通过」「驳回」，驳回必须填原因。
- 另有一个「已上架」页签，可以搜索，对任一项「撤回」，同样必须填原因。

### 5.2 作者这边

**统一的「上架」面板：**

- 出现在五类内容原来的「发布范围」位置：
  - 书：分享对话框；
  - 知识库：设置；
  - 精通之路：发布对话框；
  - 练习集：编辑页；
  - 课程：课程页。
- 面板内容：
  - 当前状态，以及最近一次驳回或撤回的原因；
  - 上架信息表单；
  - 按状态出现的按钮：提交上架、撤回申请、下架、重新上架；
  - 加入人数。

**老师工作台、管理员首页加一块「我上架的内容」：**

- 每项显示状态和加入人数。
- 缺学段或学科的标「待补分类」，点进去就能补。
- 管理员首页另显示待审数量。

### 5.3 学习者这边

- 各列表里，加入的内容照现在的样子显示。来源标签：管理员上架的显示「平台发布」，老师上架的显示老师名字。
- 学生首页原来的「学校发布的新内容」改成「平台新上架」：最近 30 天上架的内容，最多 6 项，点开进介绍页。

## 6. 预置分类

- 放在代码里，就是上级文档附录 A 的清单。
- 每项一个固定 id，例如：
  - 学段：`stage.university`
  - 一级学科：`univ.engineering`
  - 二级学科：`univ.engineering.computer`
  - 中小学学科：`k12.primary.math`
- 第 2 批加管理员调整时，库里只存调整的部分，id 不变。
- 显示名六种语言都有。附录 A 的名称是中文，其他语言给对应译名。

## 7. 旧数据迁移（上级 9.1）

**对象：** 作者是老师或管理员、而且对所有人开放的内容。包括：

- 发布范围选了「全部」的；
- 没有发布范围记录、但已公开的旧书和旧知识库。

**怎么处理：**

1. 建上架记录，状态「已上架」，来源记为迁移。标题、简介取内容本身的；学段、学科、难度、标签留空。
2. 发布范围的「全部」改成空。下面这些人自动算「已加入」（迁移来源）：

| 内容 | 谁算已加入 |
|---|---|
| 精通之路 | 副本里答过题的人 |
| 练习集 | 交过的人 |
| 课程 | 完成过其中任务、或交过作业的人；课程里任务的「全部」范围也改成空，改由课程成员带入 |
| 书 | 有阅读进度的人 |
| 知识库 | 没有记录可查，不自动加入，需要的人去市场加入 |

3. 没动过的人不算加入。原来自动给他们的精通之路副本只是不显示，答题记录本来就没有。

**另外：**

- 学段、学科为空的内容：在市场的「全部」和关键词搜索里能看到，但不出现在学段、学科筛选的结果里。作者和管理员会看到「待补分类」。
- 学生以前公开过的书、知识库不动。
- 迁移在后端启动时自动跑一次，记下已完成，可以重复运行。跑之前先备份发布范围库和上架库。
- 单独发给所有人的任务，本批不动（第 2 批处理）。

## 8. 后端

**新模块 `deeptutor/catalog/`：**

| 文件 | 内容 |
|---|---|
| `taxonomy.py` | 预置分类、校验 |
| `store.py` | 系统库 `<SYSTEM_ROOT>/catalog.sqlite3`：上架、审核记录、加入、迁移记录。沿用系统库约定：读不建库、读不出不放行、写事务不嵌套 |
| `listings.py` | 上架状态和检查 |
| `enrollment.py` | 加入、退出、课程带入 |
| `market.py` | 查询、筛选计数、排序 |
| `preview.py` | 介绍页预览和审核预览 |
| `migration.py` | 9.1 的迁移 |

**接口：**

| 接口 | 说明 |
|---|---|
| `GET /api/catalog/taxonomy` | 分类 |
| `GET /api/catalog/items` | 市场列表。参数：q、stage、subject、kind、difficulty、tag、author、sort、page。返回结果和各条件的计数 |
| `GET /api/catalog/items/{kind}/{id}` | 介绍页 |
| `POST/DELETE /api/catalog/items/{kind}/{id}/join` | 加入、退出 |
| `GET /api/catalog/authors/{id}` | 作者主页 |
| `GET /api/catalog/listings/mine` | 我上架的内容 |
| `GET/PUT /api/catalog/listings/{kind}/{id}` | 上架信息 |
| `POST .../submit`、`/withdraw-request`、`/unlist`、`/relist` | 作者的动作 |
| `GET /api/catalog/review`、`GET /api/catalog/review/{kind}/{id}` | 审核列表和审核预览 |
| `POST .../approve`、`/reject`、`/take-down` | 管理员的动作 |

**改已有代码（只加最少的接入点）：**

| 位置 | 改什么 |
|---|---|
| 发布范围 `get_scope` | 读取时合入加入成员；已撤回时清空接收者 |
| 首次发布 | 没选接收者时存「空」，不再默认任教班级，不再报「请选择接收者」 |
| 课程 | 发布不再要求有接收者；覆盖检查换成 4.3 的规则；加任务时给成员补加 |
| 书、知识库、精通之路、练习集、课程的归档、设为私有、删除 | 同步上架记录 |
| 来源标签 | 「school」的显示文字改成「平台发布」，判断逻辑不变 |
| 首页 | 「学校发布」区块换成「平台新上架」 |
| 账号删除 | 删他的加入记录；老师离开、内容转交时，上架记录的作者跟着转 |
| 通知 | 加 `listing_submitted`、`listing_approved`、`listing_rejected`、`listing_taken_down` |

## 10. 测试和完成标准

**后端：**

- 状态机：每条转换，以及不允许的转换。
- 权限：学生不能上架；非作者不能改；只有管理员能审、能撤回；驳回和撤回不填原因不行。
- 提交前检查：每类一条。
- 加入、退出、再加入：精通之路副本和进度恢复；练习成绩保留；书的阅读进度保留。
- 撤回后成员打不开，重新通过后恢复。
- 课程带入：加入课程后，课程任务和引用的内容都能用；退出后自己单独加入的保留；课程加任务后成员补上。
- 课程引用别人没上架的内容被拒。
- 市场：多条件组合、计数（放开本项）、关键词、两种排序、分页、空分类不进筛选。
- 迁移：「全部」的五类内容各一条；动过和没动过的人；重复运行；备份文件生成。
- 老师、管理员不能加入精通之路、练习集、课程（本批限制）。

**前端：** 市场筛选和地址同步、上架面板各状态、审核页、加入按钮、六种语言检查。

**浏览器实测：**

1. 老师建一套练习集和一本书，填分类上架。
2. 管理员驳回书（写原因），老师看到原因，改后再提交。
3. 管理员通过两项。
4. 学生在市场按学段、学科、类型组合筛选和搜索找到，看介绍页，加入。
5. 学生在练习集列表里作答、在书架里读书。
6. 作者主页显示加入人数。
7. 老师下架后学生仍能学；管理员撤回后学生打不开，重新通过后恢复。
8. 迁移：准备一个「全部」范围的旧精通之路，确认答过题的学生仍在学、在市场里能搜到。

**全量测试：** 后端、前端全部通过，然后本地提交，不推送。

## 11. 风险

- 「读取范围时合入成员」会让每次访问判断多读一次上架库。表上加索引；必要时一次请求内缓存。
- 精通之路的分配目前只给学生，本批的加入限制就是为了不碰这一块；第 2 批要放开时，再改分配和副本的角色判断。

## 12. 实现时的调整（2026-11-03）

- **发布时不选接收者**：新界面发布时带「只靠加入」标记，后端存空的接收者。没有带这个标记的旧调用（比如补练）仍按原来的规则发给任教的班或选中的学生，到第 2 批去班级时一起改。
- **撤回后的拦截**：管理员撤回时另记一个「已拦截」标记。作者重新提交后进入待审核，拦截仍然有效，直到管理员再次通过才解除。这样不会出现「一提交就恢复」的空档。
- **分类名称**：预置分类带中文和英文名，界面是其他语言时显示英文名。
- **学科筛选**：没有选学段时，学科选项不标学段，比如「数学」不区分小学、初中。选了学段后就只列这些学段下的学科。
- **账号删除和转交**：交接流程加了一步「catalog」：上架记录跟着内容转给接手人，被删账号的加入记录一并删除。
- **浏览器实测已覆盖**：老师发布练习集（不用选发给谁）→ 填分类上架 → 管理员驳回（不填原因不让驳回）→ 老师看到原因、重新提交 → 管理员通过 → 学生在市场按学段筛选、按关键词搜索 → 看介绍页（不露题目）→ 加入 → 去作答；没加入的学生收不到；首页「平台新上架」；作者主页的加入人数；管理员撤回后学生打不开，重新通过后恢复。
- **浏览器实测未覆盖**：书、知识库、精通之路、课程的上架和加入。测试环境没有模型，建不出书和知识库，这几类只有自动测试覆盖。
