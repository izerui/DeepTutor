# 教师精通之路与知识库共享 —— 设计方案

> 状态：待评审
> 日期：2026-10-22
> 范围：老师创建精通之路，学生按老师大纲学习；知识库统一登记，只保留一份，按公开 / 私有 / 通过引用可读三种方式访问。
> 不在范围内：班级/教学分组、教师看板、教学统计、作业、通知、按周开放章节。

---

## 1. 目标

1. 管理员或教师创建精通之路，确定大纲后**发布给指定学生**。
2. 学生登录后直接看到分配给自己的路径，**不需要生成或确认大纲**，点开就能学。
3. **大纲由老师控制**。学生和 AI 都不能增删改课程知识点，但讲解方式和练习难度可以按学生情况调整。
4. **每个学生的学习记录独立保存**，学生之间、学生与老师之间互不影响。
5. 老师修改大纲后，通过"发布更新"同步给学生，并按规则迁移已有进度。
6. 知识库**只有一份**，访问方式分为公开、私有、通过引用可读三种；所有功能都只引用，不再复制。

## 2. 现状（基于当前代码）

| 方面 | 现状 | 影响 |
|---|---|---|
| 角色 | `deeptutor/multi_user/models.py` 中 `Role = admin/teacher/student/user`，但授权只判断 `is_admin`（`require_admin()` 位于 `api/routers/auth.py`） | 教师角色需要真正接入权限判断 |
| 学生限制 | 通过 `preset="learner"` + `learning_policy` 实现，带有低龄学习限制 | "学生"身份与 learner 预设需要分开，成年学生不能被自动套上低龄限制 |
| 精通之路存储 | `LearningStore` 按账号 workspace 隔离，数据落在各自的 `mastery.sqlite3` | 老师创建的路径学生看不到 |
| 路径数据 | 一个 `LearningProgress` 同时包含大纲（模块、知识点、前置关系）和个人状态（`mastery_levels`、`quiz_attempts`、`learning_evidence`、`review_queue`、`pending_question`、`learner_profile`） | 不能直接共享老师的路径，必须把"大纲"和"个人状态"拆开 |
| AI 改大纲 | `capabilities/mastery/mode.py` 中 AI 可以切换模式，再调用 `mastery_build` / `mastery_revise` | 只在前端隐藏按钮不够，工具层也要拦截 |
| 手动修改入口 | `PUT /topics/{id}/map`、`POST /topics/{id}/objectives/{kp}/override`、`/progress/{id}/init-modules`、`import-from-book`、`generate-from-*`、`redo`、`DELETE` 等 | 学生对教师路径调用这些接口时都需要拒绝 |
| 资料来源 | `TopicSource` 支持 book / notebook / knowledge_base / file / chat / question_bank / cowriter 等 | 分发给学生时只允许可共享的来源 |
| 知识库 | 有管理员知识库（`admin:kb:`）、账号知识库（`user:kb:`）和按授权分配（`knowledge_access.py` + `grants`） | 需要统一登记，支持公开 / 私有 / 通过引用可读 |
| 可复用能力 | `assign_objective_identities()`、`learning/migration.py`、`outline_revision.py` | 大纲版本迁移可以在此基础上实现 |

## 3. 角色与权限

### 3.1 角色定义

| 角色 | 说明 |
|---|---|
| `admin` | 管理全部账号、全部教师路径、全部知识库 |
| `teacher` | 创建并维护自己的教师路径，分配给学生，维护自己的知识库并可设为公开 |
| `student` | 学习分配给自己的路径，只读公开库和路径引用的库 |
| `user` | 普通账号，行为保持现状 |

- 新增 `require_teacher_or_admin()`，教师相关接口统一使用它。
- `student` 是**教学身份**，`learner` 是**功能预设**，二者独立：学生账号可以不使用 learner 预设，learner 预设账号也不一定是学生。
- 后台用户管理页支持把角色设为 `teacher` / `student`（目前只能在 admin 和 user 之间切换）。

### 3.2 权限矩阵

| 操作 | 管理员 | 教师 | 学生 | 普通用户 |
|---|:-:|:-:|:-:|:-:|
| 创建教师路径 | ✓ | ✓ | ✗ | ✗ |
| 编辑大纲、发布、发布更新 | 全部 | 仅自己的 | ✗ | ✗ |
| 分配或撤销学生 | 全部 | 仅自己的路径 | ✗ | ✗ |
| 学习已分配的教师路径 | ✓ | ✓（试学） | ✓ | ✗ |
| 修改教师路径的大纲或掌握状态 | — | — | ✗ | — |
| 创建个人精通之路 | ✓ | ✓ | 可配置（默认允许） | ✓ |
| 对教师路径"重学"（清空自己的实例状态） | — | ✓ | ✓ | — |
| 查看、检索公开知识库 | ✓ | ✓ | ✓ | ✓ |
| 创建私有知识库 | ✓ | ✓ | 由管理员配置，默认不允许 | ✓ |
| 把知识库设为公开 | ✓ | ✓（仅自己的库） | ✗ | ✗ |
| 修改或删除知识库资料 | 全部 | 仅自己创建的 | 仅自己的私有库 | 仅自己的私有库 |

## 4. 数据模型

核心是把**路径模板（大纲）**和**学习实例（个人状态）**分开存储。

### 4.1 存储位置

新增一个系统级数据库，例如 `data/system/teaching.sqlite3`，不放在任何账号的 workspace 下。它保存模板、版本和分配关系。学生的学习实例仍然存在**学生自己的** `mastery.sqlite3` 中，可以复用现有 `LearningStore` 的全部学习逻辑。

### 4.2 表结构（概要）

```text
mastery_templates                -- 教师路径
  id                 TEXT PK
  owner_user_id      TEXT        -- 创建教师
  title              TEXT
  description        TEXT
  status             TEXT        -- draft | published | archived
  current_revision   INTEGER     -- 最新发布的版本号，0 表示未发布
  draft_path_id      TEXT        -- 教师 workspace 中用于编辑和试学的路径
  created_at / updated_at

mastery_template_revisions       -- 已发布版本的不可变快照
  template_id        TEXT
  revision           INTEGER
  outline_json       TEXT        -- 模块、知识点（含稳定 kp_id）、前置关系、通过标准
  sources_json       TEXT        -- 引用的公共资料（kb_id / doc_id / 范围 / 资料版本）
  change_log_json    TEXT        -- 相对上一版的变更：kp_id → unchanged|reworded|added|removed|redefined
  published_by       TEXT
  published_at       TEXT
  PK(template_id, revision)

mastery_assignments              -- 分配关系
  template_id        TEXT
  student_user_id    TEXT
  assigned_by        TEXT
  status             TEXT        -- active | revoked
  instance_path_id   TEXT        -- 学生 workspace 中的实例 id（首次进入时创建）
  applied_revision   INTEGER     -- 学生实例当前使用的版本
  assigned_at / revoked_at
  PK(template_id, student_user_id)
```

### 4.3 学生实例

- 学生**第一次进入**时，根据 `current_revision` 的快照在学生 workspace 中创建 `LearningProgress`，并打上标记：
  `origin = {kind: "teacher_template", template_id, revision}`。
- 实例中的大纲字段视为**只读副本**，个人状态字段（掌握度、答题、复习、会话、待答题）照常读写。
- 同一模板重复分配时，复用已有的 `instance_path_id`，不会重新创建，也不会清空记录。

### 4.4 教师编辑与试学

- 教师用现有的精通之路功能在自己的 workspace 里编辑 `draft_path_id`：AI 生成、手动编辑、试学都能直接复用。
- **发布**时只从草稿中提取大纲和资料引用生成快照，**不带上**教师试学产生的答题和掌握度。

## 5. 核心流程

### 5.1 发布

1. 教师在精通之路中点击"发布给学生"（首次发布时把这条路径登记为模板）。
2. 发布前检查：
   - 大纲非空，每个模块至少有一个知识点，前置关系没有环（复用 `_validate_runnable_modules`）。
   - 资料来源按第 7.4 节处理：公开库直接通过；自己的私有库选择“设为公开”或“通过引用可读”；个人连接器以及 notebook、chat、question_bank、cowriter、个人书籍等来源**阻止发布**并提示替换。
   - 引用的知识库和文档存在且已完成索引。
3. 生成 `revision = n + 1` 的快照，并给知识点分配稳定 `kp_id`（复用 `assign_objective_identities()`）。
4. 选择学生（选择器接口只返回 `id / username / avatar`，不开放用户管理权限），写入 `mastery_assignments`。

### 5.2 学生学习

1. 学生的精通之路列表中多出"老师布置"分组，卡片上显示来源教师、进度和下一步。
2. 点击后：如果还没有实例就创建，然后**直接进入 Study**，跳过 Outline。
3. 学习、提问、请求提示、做题、复习都使用现有流程。
4. 大纲页可以查看，但编辑相关按钮全部隐藏。

### 5.3 发布更新与进度迁移

1. 教师修改草稿后点击"发布更新"，系统生成新快照并计算 `change_log`：
   - 已有知识点：由教师在发布确认页标注为"仅调整文案"或"学习目标已改变"，系统提供默认建议。
   - 判断依据是稳定 `kp_id`，**不能只凭名称相同就继承掌握度**。
2. 发布确认页展示：受影响的学生人数，以及每类变更涉及的知识点。
3. 学生**下次开始学习时**应用新版本；如果当前有待回答的题目，答完后再应用：

| 变更类型 | 学生进度处理 |
|---|---|
| 顺序调整 / 文案修改（目标不变） | 保留掌握度与记录 |
| 新增知识点 | 加入大纲，状态为未学习 |
| 删除知识点 | 从当前大纲移除，历史答题记录保留 |
| 学习目标实质改变 | 只把该知识点的掌握度重置为待重新评估，其他知识点不受影响 |
| 前置关系变化 | 按新关系重新计算可学习的知识点 |

4. 迁移完成后更新 `applied_revision`，并在学生侧提示"老师更新了课程"。

### 5.4 撤销与停止提供

- **撤销某个学生**：`status = revoked`。该学生的列表中不再出现这条路径，相关接口和 WebSocket 拒绝访问；实例数据保留，重新分配后可以继续学。
- **停止提供（归档）**：`status = archived`，所有学生不能再进入，数据保留。
- **删除**：只能删除未发布、从未分配过的模板。已分配过的模板只能归档。

## 6. 防止绕过大纲的拦截点

学生访问的路径如果是教师模板实例，以下操作一律拒绝，返回 403 和明确提示：

- API：
  - `PUT /topics/{id}/map`
  - `POST /topics/{id}/objectives/{kp}/override`
  - `/progress/{id}/init-modules`
  - `import-from-book`
  - `generate-from-notebook`
  - `generate-from-reading`
  - `PATCH` 重命名
  - `DELETE`
  - 注：`redo` 允许，只清空学生自己实例的个人状态，大纲保持当前版本
- AI 工具：在 `mastery_mode` / `mastery_build` / `mastery_revise` 的执行入口检查实例来源。教师模板实例只允许学习和复习类模式。学生说"帮我删掉这一章"时，AI 应该说明大纲由老师制定，同时提示可以反馈给老师。
- 实现方式：在 `LearningService` 或 router 层增加统一的 `ensure_outline_mutable(path_id)`，所有修改大纲的入口都调用它，避免逐个接口遗漏。

## 7. 知识库

### 7.1 基本原则

**每个知识库在系统中只有一份，所有使用方都只引用它，不再复制。** 访问方式只有三种：

| 访问方式 | 谁能读 | 说明 |
|---|---|---|
| 公开 | 所有登录用户 | 出现在公开目录，可浏览、可检索，聊天里可用 |
| 私有 | 创建者本人（管理员可兜底管理） | 只出现在创建者自己的知识库列表里 |
| 通过引用可读 | 引用方授权范围内的用户 | 库本身仍是私有的，不出现在公开目录，只在引用它的地方可读。例如被分配了某条教师路径的学生，只能在学这条路径时检索和查看引用片段 |

- 精通之路、课程、教材、学习伙伴、聊天、写作、出题、研究等功能都只保存知识库的**固定 ID 引用**。
- 学习伙伴不再复制知识库（现状是用 `copytree` 整份复制），公开库和私有库一律改为引用源库。
- 上传人只作为维护和追溯信息。是否公开由创建者决定，管理员可以兜底。

### 7.2 知识库登记表

新增一张系统级知识库登记表，作为所有知识库的统一入口：

```text
kb_registry
  kb_id          TEXT PK   -- 固定 ID，引用统一写成 kb:<kb_id>
  name           TEXT      -- 显示名称，允许重名，按 ID 区分
  location       TEXT      -- 实际存放的 base_dir + 目录名（文件不移动）
  kind           TEXT      -- 上传库 / 个人连接器（obsidian、linked、marginnote、ima、weknora、lightrag_server、subagent 等）
  visibility     TEXT      -- public | private
  created_by     TEXT
  created_at / updated_at

kb_references
  kb_id          TEXT
  referrer_kind  TEXT      -- mastery_template | course | book | partner | ...
  referrer_id    TEXT
  doc_ids        TEXT      -- 可选，只引用部分文档或章节
  created_by     TEXT
```

- 现有的 `admin:kb:`、`user:kb:`、`account:kb:`、`workspace:<wsid>:kb:` 和裸名称引用，都通过别名映射到 `kb_id`，旧数据不需要一次性改写。
- `resolve_kb` 按下面的顺序判断读取权限：
  - 公开库：所有登录用户可读。
  - 私有库：创建者可读。
  - 被引用的私有库：按 `kb_references` 判断当前用户是否在引用方的授权范围内。
- 文档也分配固定 ID，并记录内容版本。

### 7.3 读写权限

| 操作 | 管理员 | 教师 | 学生 | 普通用户 |
|---|:-:|:-:|:-:|:-:|
| 读、检索公开库（包括在聊天中使用） | ✓ | ✓ | ✓ | ✓ |
| 创建私有库、上传文档 | ✓ | ✓ | 由管理员配置，默认不允许 | ✓ |
| 把库设为公开 | ✓ | ✓（仅自己的库） | ✗ | ✗ |
| 修改、删除库或文档 | 全部 | 仅自己创建的 | 仅自己的私有库 | 仅自己的私有库 |
| 强制撤回公开、强制删除 | ✓ | ✗ | ✗ | ✗ |

- 学生在聊天里使用公开库**一律允许**。`apply_learning_policy` 不再清空知识库，只过滤掉学生无权读取的私有库和连接器。
- 公开库**不受 workspace 白名单限制**，在所有 workspace 都能用，白名单只约束私有库。
- 个人连接器（Obsidian、本地文件夹、MarginNote、IMA、WeKnora、LightRAG 服务、子代理）**始终私有**，不能设为公开，也不能被共享引用，因为它们指向个人设备、路径或凭据。

### 7.4 教师路径引用知识库的完整流程

**发布时，按资料来源分别处理：**

| 路径引用的资料 | 处理方式 |
|---|---|
| 公开库 | 直接通过 |
| 老师自己的私有库 | 弹窗二选一，默认选第一项：**① 设为公开**；**② 通过引用可读**（库仍私有，只有被分配了这条路径的学生在学这条路径时可读） |
| 别人的私有库 | 老师看不到，无法引用 |
| 个人连接器 | 不能发布。提示老师把资料上传到一个普通知识库，再改为引用该库 |
| 笔记、聊天记录、写作草稿、个人书籍 | 不能发布，提示同上。系统不会自动复制这些内容 |

**学生侧：** 被分配了路径的学生，在学这条路径时可以直接检索路径引用的所有知识库，也能查看引用原文，不需要额外授权。辅导和出题的检索范围默认只限于老师指定的库和文档。

**发布之后：**

| 发生的事 | 处理方式 |
|---|---|
| 老师新增或修改文档 | 学生立即用到新内容，文档版本可追溯 |
| 老师删除被引用的文档 | 先列出受影响的路径，默认禁止删除，需要先替换或解除引用 |
| 公开库改回私有 | 被别人的路径、课程或伙伴引用时不能撤回；只被自己的路径引用时，可以改为“通过引用可读” |
| “通过引用可读”改为公开 | 随时可以 |
| 删除整个库 | 只要还有已发布的路径在引用，就禁止删除，需要先归档路径或替换资料 |
| 管理员强制撤回或删除 | 允许。受影响的路径标为“资料不可用”，老师在路径页看到提示；学生看到“课程资料暂不可用”，**AI 不会改用自身知识继续讲** |
| 撤销某个学生的分配，或归档路径 | 该学生对“通过引用可读”资料的访问立即失效，公开库不受影响 |
| 老师账号被删除或停用 | 老师的库和路径转给管理员，引用不变，学生继续学习 |
| 学生在聊天中使用“通过引用可读”的库 | 不能，只能在对应的路径里使用 |

### 7.5 其他功能的调整

| 功能 | 调整 |
|---|---|
| 知识库管理页 | 统一列表，分为“公开库 / 我的私有库 / 我的连接器”三栏，显示创建人和引用情况，删除前展示有哪些引用 |
| 聊天、写作、出题、研究 | 知识库选择器列出公开库、自己的私有库和自己的连接器，统一按 `kb_id` 引用 |
| 课程（`courses_state._knowledge_base_index`）、教材健康检查（`book/kb_health`）、伙伴运行时、就绪检查、记忆快照 | 这些地方目前直接调用 `current_kb_manager()`，绕过了统一解析，只能看到当前账号的库，改为通过登记表查找 |
| 学习伙伴 | 不再复制知识库，公开库和私有库都改为引用源库 |
| 管理员共享的教材 | 引用的知识库按登记表解析，对方无权读取时提示资料不可用 |
| 默认知识库、PocketBase 同步 | 改为按 `kb_id` 记录，避免不同账号同名冲突 |
| 账号删除 | 公开库和被引用的库转给管理员，不随账号一起删除 |
| 网页、GitHub 来源的定时同步 | 按登记表遍历，覆盖 workspace 中的库 |

### 7.6 知识库授权（grants）下线

公开库已经覆盖了“管理员把知识库分给用户”的用途，`grants` 里的 `knowledge_bases` 整体下线，涉及：

- `_assigned_admin_names`，以及普通用户以只读方式访问管理员库的那条分支。
- 后台授权编辑器（`GrantEditor`）中的知识库一栏。
- 移动或迁移知识库时，因为存在授权而被拦住的检查。

`grants` 中的模型、技能、伙伴、工具和 `learning_policy` 保持不变。

### 7.7 现有数据迁移

1. 给所有现有知识库（管理员库、账号库、workspace 库）登记 `kb_id`，文件不移动；连接器在 `kind` 中标为对应的连接器类型。
2. 管理员库**默认不公开**，由管理员在迁移页勾选哪些公开。**曾经授权给任何用户的管理员库自动公开**，保证原来被授权的用户不会失去访问。
3. 账号库和 workspace 库保持私有，由创建者自己决定是否公开。
4. 学习伙伴现有的复制副本，迁移后改为引用源库。如果源库已经不存在，就把副本登记为伙伴创建者的私有库，并提示创建者处理。
5. 旧的引用字符串通过别名继续有效，再按需逐步改写为 `kb:<kb_id>`。

### 7.8 书籍

书籍是 AI 根据知识库、笔记、聊天记录生成的互动教材（章节、页面、练习、进度），不是向量库，但采用与知识库**完全相同的共享规则**：

- **一份、只引用、不复制**；访问方式同样只有 公开 / 私有 / 通过引用可读 三种（D20）。
- 新增书籍登记（固定 `book_id`、实际存放位置、创建人、可见性），旧的书籍引用通过别名继续有效。
- **编辑权限只有创建者和管理员**（D21）。现有“共享书架 + 逐本授权（无 / 只读 / 可编辑）”退役；迁移时列出原来拥有“可编辑”授权的用户和书目，提示管理员处理（例如把书转给该用户）。
- 每个读者的阅读进度、练习记录各自独立（沿用现有的学习叠加层 `BookLearningOverlay`）。
- **书籍也是知识库的引用方**：书籍设为公开或被引用可读时，它引用的私有知识库必须先公开，或登记为“通过引用可读”（书籍的读者阅读这本书时可检索这些库）；与教师路径引用私有库的规则一致。
- **教师路径引用书籍**：与引用知识库的规则一致——公开书籍直接通过；自己的私有书籍二选一“设为公开 / 通过引用可读”；别人的私有书籍看不到。
- 创建书籍的能力沿用现有的按账号 `create` 开关。
- 迁移（D22）：共享书架（管理员工作区）上曾对任何用户可见的书（默认只读，或有人被授权只读 / 可编辑）自动公开，其余为管理员私有；用户自己的书保持私有。

## 9. 实施分期

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 角色与权限 | `require_teacher_or_admin`，后台可以设置 teacher / student，与 learner 预设解耦 | 教师可以访问教师接口，学生和普通用户被拒绝 |
| P2 模板与分配 | 系统库建表、发布快照、分配、学生实例创建、列表展示 | 老师发布后，两名学生各自学习、进度互不影响 |
| P3 只读拦截 | API + AI 工具的统一 `ensure_outline_mutable` | 学生通过接口或对话都改不了大纲 |
| P4 发布更新与迁移 | change_log、按版本迁移、延迟到下次学习时应用 | 更新后旧进度按规则保留，新增知识点为未学 |
| P5 撤销与归档 | 撤销、归档、重新分配后继续 | 撤销后学生无法进入，重新分配后进度恢复 |
| P6 知识库登记与共享 | 登记表与固定 ID、三种访问方式、读写权限、检索范围限制、引用保护、伙伴改为引用、grants 知识库下线、迁移工具 | 学生能读公开库和路径引用的库但不能改；被引用的资料不能直接删除；伙伴不再复制 |

**端到端验收场景**：老师发布并分配给学生 A、B → 两人独立学习 → 老师更新大纲并迁移进度 → 撤销 B 的访问 → A 不受影响，B 的历史记录保留。

工作量粗估：P1 至 P5 约 2 到 3 周；P6 取决于现有知识库索引改造的难度，约 1 到 2 周。方案确认后再拆成任务细化估算。

### 10.1 实施中确定的细则（由实施方决定，已告知用户）

| # | 细则 |
|---|---|
| R1 | 不单独做“管理员迁移页”：管理员在知识库页 / 书籍页用可见性开关控制公开；管理员设置页提供一次性的“迁移结果”说明，列出自动公开的库和书、停用的连接器授权、原“可编辑”书籍授权 |
| R2 | 个人连接器只允许被**同一创建者**的学习伙伴引用，不能被其他账号以任何方式读取 |
| R3 | 自己的库和书继续接受旧格式引用（名称、`account:kb:` 等），通过别名解析；新写入的引用统一为固定 ID |
| R4 | 只有 student 账号能被分配教师路径；教师通过草稿试学 |
| R5 | 学生的教师路径实例创建在学生的默认工作区 |
| R6 | 账号删除后，其知识库、书籍、教师路径统一转给执行删除的管理员（无登录身份时为本地管理员） |
| R7 | 学习伙伴旧副本找不到源库时，登记为伙伴创建者的私有库，并在伙伴页面提示创建者 |
| R8 | 教师路径的辅导和出题检索**只用路径引用的库**；按文档范围收窄需要检索工具支持文档过滤，不支持时先按库收窄 |

| R10 | 课程、书籍登记为知识库的引用方；网页 / GitHub 定时同步按登记表遍历；所有入库方式（上传、zip、文件夹同步、网页同步）都记录文档 ID 和版本 |

### 10.2 合并后补充的规则与已批准的例外（用户 2026-10-27 / 2026-10-28 确认）

编号对应跟进清单 `docs/superpowers/plans/2026-10-27-post-merge-followups.md` 第 0 节（为避免与 10.1 的 R1–R12 混淆，这里记为 F1–F5）。

| # | 规则 |
|---|---|
| F1 | 别人可以把老师的公开库 / 公开书加入课程、伙伴或自己的书；**所有者始终可以撤回公开或删除**，不会因为他人引用而被阻止。撤回或删除后，引用方记撤销记录并显示“资料不可用”。被他人**已发布的教师路径**直接或经书间接引用时，允许撤回，但先弹窗列出受影响的路径数和学生数（只给数量，不暴露对方 ID），确认时须携带所示计数，计数变化则重新询问 |
| F2 | 学生经教师路径阅读“仅引用”的书时，可以记录自己的阅读进度、书签和书内测验，数据写入学生自己的学习覆盖层，不改动书本身 |
| F3 | 撤销或归档分配时，服务端主动关闭该学生对此路径的实时订阅（终止消息带 `teacher_path_unavailable` 代码），学生页面即时切换为“课程不可用” |
| F4 | **已批准的例外**：教师路径的检索在检索工具不支持文档过滤时按整库进行（见 10.1 R8），此时可能返回库内未被路径单独指定的文档名称和片段。建议老师把需要限定的文档单独建库 |
| F5 | **已批准的例外**：同一会话里学生先走个人路径、再切换到教师路径时，之前对话中已出现的个人资料内容仍保留在会话历史（存档与回放）中。会话属于学生本人，老师看不到；教师路径的资料范围（10.1 R8）只约束切换后的检索与原文读取，不回溯过滤已有历史 |
| F6 | 源工作区已归档的公开书：管理员可以设为私有，也可以删除。删除只注销登记并撤销全部引用，**不改动归档目录中的任何文件**；工作区恢复后，这本书以原所有者的私有本地书重新出现。所有者在归档期间不能修改可见性或删除 |
| F7 | learner 策略的账号：前端外壳不请求、不显示其学习面之外的入口和检查（设置、工作区、伙伴、工具、版本检查等），后端拒绝策略保持不变 |
