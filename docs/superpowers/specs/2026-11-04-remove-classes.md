# 删除班级功能（2026-11-04）

> 状态：用户同意（2026-11-04）。生产环境从未建过班级，所以不再保留班级代码，也不再需要「停用班级」这一步迁移。上线前需在服务器上确认生产数据里确实没有班级数据（见第 4 节）。

## 1. 删掉的

- **后端：**
  - 整个班级模块：班级、学生名单、任课老师、邀请链接和邀请、院系年级、班级公告、班级报告、按班的学生权限和 AI 用量；
  - 班级接口：`/api/classes`、`/api/class-invites`；
  - 「停用班级」迁移，以及代码里所有「停用前/停用后」的两套逻辑；
  - 发布范围里的「发给班级」「发给院系年级」；
  - 「首次发布默认发给任教的班」，以及没有班可选时的报错；
  - 「作业优先转给同班另一位老师」；
  - 老师重置本班学生密码；
  - 注册时凭班级邀请入班、关闭注册时凭邀请也能注册；
  - 旧的「资料被收窄时通知路线作者」（班级时代的做法，已有新的资料撤回通知代替）。
- **前端：** 班级页 `/classes`、邀请页 `/join/…`、两种班级通知的文字、登录页里转交邀请码的逻辑，以及这些地方用到的翻译文字。

## 2. 留下并改为直接按新规则运行的

- **谁能收到内容：** 加入的人；或者被点名的人，比如补练发给指定的学习者；以及上线前就设为「所有人」的旧数据。
- **老师的学习者：** 加入了这位老师内容的人。用在练习集成绩、补练能发给谁、精通之路手动加人、需要关注这几处。
- **学生权限：** 个人设置优先，其次是系统默认。AI 每日用量：个人设置优先，其次是全校默认。
- **任务：** 只能放在课程里发布。离任老师的任务和作业一律转给接手人；管理员可以再把课程或任务转给一位老师批改。
- **注册：** 开放注册时谁都可以注册；关闭时只能由管理员建账号。旧链接里的邀请参数会被忽略。

## 3. 原来放在班级模块里、其实与班级无关的代码，搬到了新位置

| 内容 | 新位置 |
|---|---|
| 账号读取、实时角色、结束其他会话 | `deeptutor/multi_user/accounts.py` |
| 角色变化、老师转交已发布内容、账号删除的交接步骤 | `deeptutor/multi_user/content_lifecycle.py` |
| 学习情况的计算 | `deeptutor/catalog/learner_data.py` |
| 需要关注 | `deeptutor/catalog/attention.py` |

账号删除的交接步骤里去掉了 `classes` 这一步。

## 4. 上线前确认

在部署目录执行：

```bash
ls data/system/classes.sqlite3 && sqlite3 data/system/classes.sqlite3 "select count(*) from classes; select count(*) from class_members;"
```

- 没有这个文件，或者两个数都是 0：可以直接上线。
- 不是 0：说明生产上用过班级，先不要上线，把结果发过来。

上线时，「所有人可见的内容自动上架」这一步迁移照常执行。迁移体检命令也照常可用，现在只对比这一步迁移前后的差异。

## 5. 验证

- **测试结果：**
  - 后端全量测试通过，14 个回环测试通过；
  - 前端全部测试、类型检查（不含本机开发服务器生成的文件）、六种语言检查、契约检查都通过。
- **测试的调整：**
  - 只针对班级规则的测试删掉了；
  - 其他规则（作业、练习、任务、精通之路、点评、通知、交接、AI 用量等）的测试都保留，只把准备步骤改为「学生加入了内容」或「课程里的任务」。
- **改测试时发现的问题：** 「所有人可见内容自动上架」的迁移里，有一处还在用已删除的班级字段，导致迁移会失败。已修复，相关测试恢复正常。
- **浏览器实测：**
  - 学生侧栏有「练习集」、没有「班级」，加入练习后能在练习集页看到；
  - 老师加入别人的练习，在「我加入的」里作答，得分 2/2；
  - 管理员把手里的课程转给老师，老师收到课程和通知。
- **迁移体检：** 在旧数据副本上跑，结果是 `problems: 0`。
