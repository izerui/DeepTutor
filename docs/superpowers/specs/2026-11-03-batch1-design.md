# 第 1 批详细设计：任务、作业、通知、学生首页

> 日期：2026-11-03
> 状态：已实施（2026-11-03）；实施中的调整见文末「实施记录」
> 上级方案：`2026-11-02-teaching-direction-roadmap.md` 第 5.4、5.5、5.8、5.12 节，第 6 节相关联动，第 13 节第 1 批

做完后能走通：**老师布置 → 学生收到通知 → 学生完成或交作业 → 老师批改或退回 → 学生看到结果**。

---

## 1. 范围

| 做 | 不做（留到后面的批次） |
|---|---|
| 任务：五类（精通之路、练习集、读书、作业、纯说明），截止时间，完成判定，状态 | 开放时间、日历（第 2 批） |
| 作业：提交、AI 建议分、老师批改、退回、重交 | 老师点评知识点、班级公告（第 2 批） |
| 站内通知：铃铛、未读数、列表 | 老师工作台（第 3 批），老师首页暂不变 |
| 学生首页：老师布置的、学校发布的、我自己在学的、历史 | |
| 任务看板加一列只读的「老师布置」 | |
| 账号、班级、内容变化对任务和作业的联动 | |

## 2. 页面和入口

| 谁 | 入口 | 内容 |
|---|---|---|
| 学生 | 左侧导航「首页」（新，排第一） | 三块：老师布置的（待完成、快到期、逾期）、学校发布的（最近的新内容）、我自己在学的（最近的自建精通之路）；底部「历史」入口；页面上保留「开始对话」按钮 |
| 学生 | 「首页」→ 点任务 | 任务详情：说明、截止时间、去完成的按钮（打开精通之路、练习集、书的那几章）；作业任务在这里提交、看结果 |
| 学生 | 「首页」→「历史」 | 已完成和已关闭的任务，只读，能看到自己的成绩、评语 |
| 老师、管理员 | 左侧导航「任务」（新） | 我布置的任务列表（完成人数、待批改数）；新建任务；任务详情里看每个学生的状态，批改作业 |
| 所有人 | 左侧导航底部的铃铛 | 未读数；点开是通知列表，点某一条跳到对应位置 |
| 学生 | 任务看板 | 多一列只读的「老师布置」，显示待完成的任务，点开跳到任务详情 |

- 原来的「首页」（聊天）改名为「对话」，位置不变。
- 老师、管理员的「首页」暂时还是对话页，第 3 批换成工作台。

## 3. 任务

### 3.1 内容

| 字段 | 说明 |
|---|---|
| 标题、说明 | 必填标题；说明可选 |
| 类型 | 精通之路、练习集、读书、作业、纯说明 |
| 要做的内容 | 精通之路：选一条自己发布的，再设「掌握多少算完成」（默认 100%）。练习集：选一个自己发布的。读书：选一本书和其中的章节。作业：写作业要求，可选评分要点、满分（默认 100）。纯说明：无 |
| 截止时间 | 可选 |
| 发给谁 | 按发布范围的统一规则：有任课班预选这些班，没班必须自己选；只能选班和学生；作业任务不能选「全部」 |

- 老师只能引用**自己发布的**精通之路和练习集，以及自己能读的书。
- 管理员布置的任务不能是作业（作业只属于老师和学生）。

### 3.2 发布前检查

- 引用的内容必须覆盖任务的全部接收者，否则不让发布，并列出看不到的人数，提示「先把 X 的范围放宽」。
- 引用的内容已被撤回或删除，不让发布。

### 3.3 老师那边的状态

草稿 → 已发布 → 已撤回。

- **删除**：只能删从没发布过的。
- **发布后可以改**：说明、截止时间、范围（收窄要确认人数）。截止时间改了，通知没完成的学生。
- **发布后不能改**：类型和引用的内容。要换，就撤回后重新布置。

### 3.4 学生那边的状态

| 状态 | 判定 |
|---|---|
| 待完成 | 在范围内、没完成、没过截止时间 |
| 逾期未完成 | 过了截止时间还没完成，仍可做、可交 |
| 已完成 | 见下表；完成时间晚于截止时间的标「逾期」 |
| 已关闭 | 任务被撤回，或学生不在范围内了，或引用的内容被撤回 |

**完成怎么判**：

| 类型 | 算完成的条件 |
|---|---|
| 练习集 | 交过卷 |
| 精通之路 | 已掌握的知识点达到设定比例 |
| 读书 | 指定章节的每一页都打开过 |
| 作业 | 交了，而且没被退回（被退回的回到「待完成」） |
| 纯说明 | 学生自己点「完成」，老师那边标「学生自报」 |

- 判定在学生打开首页、任务列表或任务详情时进行；一旦判定完成，就记下来，以后不会撤销（R24）。作业被退回是唯一的例外。
- 「已关闭」不记下来，按当前情况实时算，回到范围就恢复。

### 3.5 已经发出去的练习集和精通之路

- 学生收到的、没有被任何任务引用的练习集和精通之路，也显示在「老师布置的」里。
- 练习集带截止时间；精通之路不带。
- 这类条目不需要老师再建任务，完成判定和上表一样。
- 老师一旦建了引用它的任务，就只显示那个任务，不重复（R23）。

### 3.6 同一个人只算一条

学生通过多个班、或者既在班里又被单独点名，收到的同一个任务只算一条。

## 4. 作业

### 4.1 学生提交

- 内容：文字（最多 2 万字），加文件（最多 5 个，每个 20 MB，图片、PDF、Word、文本）。
- 截止前可以重交，以最后一次为准；截止后也能交，标「逾期」。
- 已批改的不能再交，除非老师退回。
- 状态：未交 → 待批改 → 已批改；老师退回时变「已退回」，学生重交后回到「待批改」。

### 4.2 AI 建议分

- 学生交上来后，AI 按作业要求和评分要点给一个建议分和两三句理由，只给老师看。
- 不算在学生的 AI 用量里。
- 会读学生交的文字，以及图片里的内容；其他文件不读。
- AI 出错或不可用，就没有建议分，不影响老师批改。

### 4.3 老师批改

- 在任务详情里按学生逐个看：文字、文件、AI 建议分。
- 可以一键采用建议分，也可以自己给分、写评语。
- 退回：写明原因，学生收到通知后重交。
- 批改或退回后，学生收到通知。
- 已批改的可以再改分和评语，学生会再收到一条通知。

### 4.4 谁能看

只有学生本人和这个任务的老师。同班其他老师和管理员都看不到。

### 4.5 存放

- 作业记录存在系统级新库 `tasks.sqlite3`。
- 附件放在 `<系统数据目录>/task_files/<任务>/<学生>/`，下载时检查身份。
- 每个学生每个任务只保留最后一次提交，记下第几次提交。

## 5. 通知

### 5.1 什么时候发

| 事件 | 发给谁 |
|---|---|
| 任务发布 | 范围内的学生 |
| 练习集、精通之路首次发布 | 范围内的学生（书、知识库公开时不发，避免刷屏） |
| 截止时间被修改 | 范围内没完成的学生 |
| 截止前 24 小时 | 范围内没完成的学生 |
| 作业已批改、被退回、分数被修改 | 这个学生 |
| 新交的作业 | 任务的老师，同一任务一天汇总成一条 |
| 收到进班邀请 | 这个学生 |
| 别人的内容转交给了自己 | 接手的管理员或老师 |

- 同一件事对同一个人只发一条：每条通知带一个去重键，比如「任务 X 截止提醒」。
- 「截止前 24 小时」不用定时程序：学生打开页面、或者看通知时检查一遍，到了就补发一条。
- 发布后才进班的学生，不补发「新任务」通知，但他的首页里能看到这个任务。

### 5.2 显示

- 铃铛上显示未读数，点开是最近的通知列表，可以全部标为已读。
- 点开某一条时重新检查权限：东西已经撤回、或者自己不在范围内了，显示「内容已不可用」。
- 通知存在系统级新库 `notifications.sqlite3`，保留 90 天。

## 6. 学生首页

| 区块 | 内容 |
|---|---|
| 老师布置的 | 待完成和逾期未完成的任务（含 3.5 的练习集、精通之路），按截止时间排，最近要截止的在前；逾期的标红 |
| 学校发布的 | 管理员发布、自己能读的书、知识库、精通之路、练习集，最近 30 天的新内容，最多 6 条 |
| 我自己在学的 | 最近学过的自建精通之路，最多 4 条，外加「新建」按钮（自建权限允许时才显示） |
| 历史 | 链接，打开已完成和已关闭的任务 |

## 7. 联动

| 事件 | 任务 | 作业 | 通知 |
|---|---|---|---|
| 学生退班、被移出、班级归档 | 只靠这个班收到的变「已关闭」（实时算） | 已交的保留，老师照常批改；不能再交 | — |
| 收窄范围 | 失去访问的人，任务变「已关闭」 | 同上 | — |
| 任务撤回 | 全部「已关闭」 | 同上 | — |
| 引用的内容被撤回 | 任务「已关闭」 | 同上 | 通知任务的老师 |
| 老师改成学生、老师账号被删除 | 任务转给执行操作的管理员 | 有作业的任务，优先转给所发班级的另一位任课老师（按班级名排第一个）；一个都没有时转给管理员，作业保持「待批改」，管理员只能撤回 | 通知接手的人 |
| 学生账号被删除 | — | 他的作业和附件删除 | 他的通知删除 |
| 学生改成老师或管理员 | 他收到的任务全部「已关闭」 | 已交的保留 | — |

## 8. 后端

- **新模块**：
  - `deeptutor/tasks/`：任务、完成记录、作业、附件、AI 建议；
  - `deeptutor/notifications/`：通知的写入、读取、去重、清理。
- **发布范围**：新增一种内容类型「任务」，复用现有的范围、预选和确认人数。
- **账号交接**：新增两个阶段，「任务」和「作业」，加进删号交接和老师改学生的转交。
- **接口**：
  - 老师：`/api/tasks/mine`、新建、修改、发布、撤回、删除、详情（每个学生的状态）、批改、退回；
  - 学生：`/api/tasks/assigned`、详情、标完成、提交作业、上传和下载附件；
  - 通知：`/api/notifications`、未读数、标已读；
  - 学生首页：`/api/home`（一次返回首页三块的数据）。
- **库**：`tasks.sqlite3`、`notifications.sqlite3` 沿用现有系统库的约定：只有写入时才建库，读取时不建文件，读不出来时不放行。

## 9. 测试和完成标准

- **后端测试**：
  - 第 3 到第 7 节的每一条规则都有测试，包括 3.4 每种类型的完成判定和第 7 节联动表的每一格。
  - 确认这些测试在没实现时会失败。
- **前端测试**：新建任务、学生提交作业、老师批改、铃铛、首页三块。
- **浏览器实测**：老师布置一个作业任务 → 学生收到通知 → 学生交 → 老师批改 → 学生看到分数和评语；另外走一遍练习集类任务和逾期标记。
- **全量测试**：后端、前端都通过。
- **提交**：本地提交，不推送。

## 10. 实施记录（与上文不同的地方）

- **首页地址**：学生首页的地址是 `/start`，不是 `/home`。项目里有一条检查，禁止前端再用 `/home` 等已退役的老路径。左侧导航第一项仍叫「首页」，登录后默认进入首页。
- **AI 建议分**：目前只读学生交的文字，不读图片和其他文件里的内容。
- **引用的内容被撤回时**：不发通知。老师的任务列表里，这类任务直接标「内容已不可用」；学生那边任务变「已关闭」。
- **老师和管理员的「首页」**：显示待批改数，以及「任务」「班级」「开始对话」三个入口。完整的工作台放在第 3 批。
- **R10（截止后公布答案的练习集，答案公布后截止时间不能往后改）**：在这一批一起实现了。
