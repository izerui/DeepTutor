# 删除作业功能（2026-11-05）

> 状态：用户同意（2026-11-05）。平台定位是学习平台（类似慕课），不带学校的管理模式。本批只删「作业」及围绕它的批改流程；其他师生交互（点评、点名发内容、需要关注、截止时间、学习报告明细、改分）本批不动，另行决定。

## 1. 删掉的

**后端**
- 任务类型「作业」：老师不能再建作业任务，课程里也不能加。任务类型剩：精通之路、练习集、书、说明（note）。
- 交作业：学生提交文字和文件、重交、迟交标记；作业文件的存放和下载。
- 批改：打分、评语、退回、改分；AI 批改建议；「仅老师可批改、管理员不能看作业」这套规则。
- 作业成绩旁的「平均分」。
- 首页「待批改」接口 `/api/home/to-grade`、工作台里的「待批改」一栏。
- 学习报告里的作业列（待批改、已退回、已批改），导出 CSV 同步去掉。
- 通知：作业已提交、已批改、已改分、已退回。
- 接口：`POST /api/tasks/assigned/{id}/submit`、`POST /api/tasks/{id}/students/{sid}/grade`、`.../send-back`、`GET .../files/{name}`。

**前端**
- 侧栏「批改」和 `/grading` 页、批改队列组件。
- 任务编辑里的「作业」类型和满分设置；学生任务详情里的交作业表单、成绩、评语、退回原因、平均分。
- 工作台「待批改」、学习报告的作业列、四种作业通知的文字。
- 只用于作业的翻译文字。

## 2. 留下的
- 课程、其余四类任务、完成状态（自动判定；说明类任务由学生自己点「完成」）。
- 管理员把手里的课程或任务转给老师（只是换作者，说明里去掉「批改」字样）。
- 账号删除时任务转给接手人（去掉作业那部分）。

## 3. 已有数据
- 启动时一次性清理（`deeptutor.tasks.service.remove_homework`）：先删作业任务的发布范围、加入记录、通知（四种作业通知，以及链接指向这些作业的新任务、开放、即将到期、截止改动、转交通知；普通任务的同类通知不动）和 `data/system/task_files/` 目录，只剩作业的课程先下架（上架中→已下架、审核中→草稿；课程本身留给作者补内容，有普通任务的课程不动），全部成功后再删作业任务本身（连同它在课程里的位置、完成记录）和提交表。中间任何一步失败，作业任务留着，下次启动接着清；附件删不掉会报错，不会被吞掉。没有作业时什么也不做。
- 老库表上的类型约束里还写着 homework，不影响使用，不重建表；新库不再包含。建作业由服务和接口拒绝。

## 4. 验证
- 后端全量测试通过（退出码 0），14 个回环测试通过。只测作业规则的测试删掉；借作业测别的规则的改用「说明」类任务。新增 `tests/multi_user/test_remove_homework.py`：旧数据清理、普通课程任务不受影响、第二次执行无事可做、清加入记录或通知失败后第二次执行能清干净、旧作业的任务通知被清掉而普通任务的同类通知保留、纯作业课程清理后不再出现在市场也不能加入而混合课程照常加入和学习、建作业被拒绝。
